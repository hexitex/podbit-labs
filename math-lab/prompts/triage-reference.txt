## Categories

**NUMERICAL** — the claim has two computable sides that can be compared.
Examples: formula A = B, series sum = constant, convergence rate, ratio/percentage claim, anything mpmath can check to 500+ digits.

**STRUCTURAL** — code can generate evidence for or against the claim.
This is the DEFAULT for anything not purely numerical. Simulation, sampling, enumeration, algorithm testing, building models, sweeping parameters, computing properties, statistical tests — if Python can produce evidence, it's STRUCTURAL. Even approximate or partial evidence counts.

**DOMAIN_EXPERT** — code cannot produce evidence, but the claim has logical content that reasoning can evaluate.
The claim makes a substantive assertion — about causal relationships, conceptual coherence, theoretical consistency, philosophical structure, or principled argument — that can be assessed for validity without running code. Use this when: the claim argues for something with internal logical structure, references principles or frameworks that can be cross-examined, or makes a falsifiable conceptual argument. The LLM evaluator will ask: Is this internally consistent? Does it follow from its premises? Does it contradict established principles?
NOT because the code would be complex — complex is fine. Only when code genuinely cannot produce any evidence at all AND the claim still has logical content worth evaluating.

**NOT_TESTABLE** — the claim has no evaluable content — even reasoning cannot adjudicate it.
Pure speculation without grounding ("might", "could", "perhaps" with no premises or argument), aesthetic or normative judgments ("X is beautiful", "Y should be preferred"), tautologies, or claims so vague that agreeing and disagreeing with them are equally valid. There is nothing here to be right or wrong about.

## Physics-as-Math Principle

Many physics claims appear to require domain-specific simulators (FDTD, FEM, QuTiP, Qiskit, circuit simulators) but are actually testable by reducing them to their mathematical core using standard scientific Python. Before classifying a physics claim as DOMAIN_EXPERT or NOT_TESTABLE, ask: "Can this be expressed as linear algebra, eigenvalue problems, ODE integration, or statistical computation?"

**Quantum mechanics** → density matrices are numpy arrays, Hamiltonians are matrices, time evolution is matrix exponentiation, entanglement is partial trace + eigenvalues, Bell inequalities are expectation values of tensor product operators, master equations are ODEs on vectorized density matrices. No Qiskit/Cirq needed.

**Wave physics / topological photonics** → tight-binding models are sparse matrices, band structures are eigenvalue problems, topological invariants (Chern numbers, winding numbers) are integrals over Brillouin zone, disorder robustness is eigenvalue statistics under random perturbation, transfer matrices give transmission/reflection. No FDTD/FEM needed.

**Optomechanics / coupled systems** → quantum Langevin equations are coupled ODEs, linearized dynamics are matrix equations, strong coupling is an eigenvalue splitting condition, zero-point fluctuations are algebraic expressions, Wigner function negativity is a numerical computation. No QuTiP needed.

**Relativistic / particle physics** → 4-vectors are numpy arrays, Lorentz boosts are 4x4 matrices, Mandelstam variables (s, t, u) are dot products of 4-momenta, phase space integrals are numerical integrals over momentum space with delta-function constraints, scattering cross-sections are integrals of matrix elements squared. No HEP packages needed.

**Many-body / condensed matter** → BCS superconductivity is a self-consistent gap equation on a BdG Hamiltonian (matrix eigenvalue problem iterated to convergence). Exciton-polaron spectral functions are computed from retarded Green's functions G^R = (omega + i*eta - H)^{-1} — just matrix inversion at each frequency. Superfluid weight is the second derivative of free energy w.r.t. vector potential — numerical differentiation of eigenvalues. Proximity effects are modeled by coupling two Hamiltonians. Self-energy, quasiparticle weight Z, Matsubara Green's functions — all reduce to matrix algebra on lattice Hamiltonians. No DMFT, no ab-initio codes, no QuTiP needed. A BCS gap equation CAN converge to zero gap (no superconductivity), so the test IS falsifiable.

**Comparative / multi-protocol claims** → Claims like "protocols A, B, C each offer distinct trade-offs in X, Y, Z" are STRUCTURAL, not survey statements. Model each protocol as a simplified quantum system (e.g., SPDC = two-mode squeeze operator on Fock space, spin-exchange = Heisenberg Hamiltonian, circuit-QED = Jaynes-Cummings model), add decoherence via Lindblad, measure fidelity/purity/entanglement, and COMPARE the metrics numerically. A claim about trade-offs is testable if you can show that protocol A scores higher on metric X but lower on metric Y.

**General rule**: if the physics reduces to matrices, ODEs, eigenvalues, or integrals — it's STRUCTURAL and testable. The only physics that is genuinely not testable is physics that requires experimental apparatus or computational methods that cannot be reduced to standard numerical linear algebra (e.g., full 3D turbulence DNS, molecular dynamics with empirical force fields at scale). A claim is NOT disqualified for being "broad", "comparative", or "many-body" — it just means more matrix algebra.

## Rules
1. Start by sketching the code approach — even one sentence like "sweep parameter X from 0 to 1 and check if Y crosses threshold"
2. If you found a code approach → NUMERICAL or STRUCTURAL
3. DOMAIN_EXPERT only if you exhausted all code ideas and none work — explain what you tried — AND the claim still makes a substantive assertion that reasoning can assess
4. NUMERICAL vs STRUCTURAL: if both sides are directly computable values → NUMERICAL. Otherwise → STRUCTURAL
5. Do NOT use DOMAIN_EXPERT because the math is "complex" or "specialized" — scipy and sympy handle that
6. NOT_TESTABLE only when the claim is pure speculation, pure aesthetics, or so vague it has no logical content — if you can say "this claim is right/wrong because..." then it's DOMAIN_EXPERT, not NOT_TESTABLE
